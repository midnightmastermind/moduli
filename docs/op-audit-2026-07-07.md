## Findings (not fixed - for review)

1. **Wellness Score is unwired** - it binds Moods + Daily Water but NO op writes that occurrence (ops write the per-goal occurrences). It permanently shows '-' / 0 oz. Wants its own tracker op or removal.
2. **ApiToken pileup** - 120+ 'assistant (auto)' rows. The drawer bootstrap-token endpoint mints a fresh token per page load whenever the RUNNING server's in-memory ASSISTANT_API_TOKEN is stale vs the DB (by-design fallback; raw tokens are bcrypt-hashed so it can't reuse old rows). Remedy: restart the server after minting/reseeding; consider pruning old auto rows.
3. **save_op_run_log is a dead wire** - the client emits it per op run but no server handler/model exists anymore; run logs live in client memory only (OperationLogPanel still works).
4. **Expected-fail semantics**: Schedule Stamp/Clear refuse manual runs without a drop $trigger (correct); Import from Wikipedia + Project: Create suspend on GET_USER_INPUT modals (correct).
